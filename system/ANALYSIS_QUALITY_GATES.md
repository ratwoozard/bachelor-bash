# ANALYSIS QUALITY GATES

Et afsnit i `report/04-analysis.md` er ikke færdigt, før relevante gates er bestået.

`[x]` bestået · `[~]` delvist · `[ ]` ikke

## Gates (alle projekter)

| Gate | Bestået | Hvad skal være sandt |
|------|---------|----------------------|
| Evidens |  | Hver hovedpåstand har konkret empirianker registreret i `EMPIRI_STATUS.md`. |
| Korrekt teoribrug |  | Teori er i `THEORY_REGISTRY.md` og matcher analyseniveau. |
| Kildegrundlag |  | Kilden er læst; usikre kilder er `[MANGLER]`. |
| Harvard author-year |  | Teorikilder i brødtekst; sidetal ved citat når verificeret. |
| QUANT/QUAL-adskillelse |  | Tydeligt skel, hvis begge datatyper indgår. |
| Triangulering uden kausalitetsclaim |  | Sammenholdning, ikke bevis for årsag. |
| Ingen pseudoanalyse |  | Teori, empiri og fortolkning er forbundet. |
| Ingen fluffy tekst |  | Ingen generiske påstande uden casekobling. |
| Delkonklusion med evidens |  | Følger af afsnittet; ingen nye claims. |
| PF-kobling |  | Afsnittet siger, hvad fundet betyder for PF i `PROJECT.md`. |
| Scope |  | Respekterer inde/ude i `PROJECT.md`. |
| Ingen opfundne data |  | Tal og citater kan pege på en fil. |

## Valgfrie gates (kun hvis teorien er registreret)

Tilpas. Slet rækker, I ikke bruger.

| Gate | Bestået | Typisk krav |
|------|---------|-------------|
| Procesnotation som artefakt |  | Notation visualiserer; forklarer ikke alene. |
| Lean som procesanalyse |  | Waste på procesniveau; menneskelig vurdering er ikke spild i sig selv. |
| DSS som beslutningsstøtte |  | Systemet støtter; det erstatter ikke automatisk beslutningen. |
| HITL som kontrol |  | Aktiv oversight, ikke "mennesket er med". |
| KPI/KQI-balance |  | Effektivitet ≠ kvalitet automatisk. |

## Røde flag (generelt)

Ikke bestået hvis teksten:

- konkluderer hovedfund på én kilde
- bruger "beviser" / "altid" / "alle virksomheder"
- introducerer teori, der ikke er i kapitel 3
- behandler `STATUS.md` som empiri
